26. NOTIFICATION REQUIREMENTS
============================================================

Implement notifications using native Android mechanisms.

Do NOT use:

- browser notifications
- web push
- Firebase Cloud Messaging for local reminders
- server-based notification scheduling
- JavaScript timers
- an Activity that must remain open
- an in-app-only notification system

For reminders where precise timing matters, evaluate and use

on WorkManager's deferred execution.

Use WorkManager only where its scheduling semantics are actually
appropriate.

60. NOTIFICATION ARCHITECTURE SUMMARY
============================================================

The final notification system should conceptually follow:

USER CREATES REMINDER
        ↓
SQLite stores reminder
        ↓
Notification Scheduler
        ↓
Android AlarmManager / appropriate native scheduler
        ↓
PendingIntent / BroadcastReceiver
        ↓
Android NotificationManager
        ↓
SYSTEM NOTIFICATION

The Activity does NOT need to remain open.

For device reboot:

BOOT EVENT
        ↓
Notification Rescheduler
        ↓
Read enabled schedules from SQLite
        ↓
Reschedule future notifications

For reminder update:

UPDATE DATABASE
        ↓
Cancel old schedule
        ↓
Create updated schedule

For reminder deletion:

DELETE DATABASE RECORD
        ↓
Cancel corresponding notification

For Period Tracker update:

UPDATE PERIOD DATA
        ↓
Recalculate predictions
        ↓
Update/cancel/reschedule relevant notifications
